# 機能要件定義書

対象: `PokeDexSearchTool_PC.py`（Tkinter 製ポケモン図鑑検索ツール）を GitHub Pages 上で同等機能として再現する。

データ: `pokedex_descriptions.csv`（28,008 行、ポケモン 1,021 種、ゲームタイトル 148 種）

- 列0: ポケモン名（`Pokemon`）
- 列1: ゲームタイトル（`Game Title`）
- 列2: 図鑑説明文（ヘッダ名は先頭スペース付き ` Description`。各説明文の先頭にもスペースが付いている）

---

## 1. アプリケーションの目的

ポケモン名、または図鑑説明文に含まれる単語で検索し、ヒットしたポケモンの一覧から詳細（バージョン別説明文）を開く。

## 2. 画面構成

1. **メインウィンドウ**（タイトル: `Pokedex Search`）
   - 検索語入力
   - 単語検索の実行
   - ヒットしたポケモン名の一覧
2. **詳細ウィンドウ**（タイトル: `{ポケモン名} の詳細`）
   - バージョン列と説明列
   - 検索語にヒットした説明行のハイライト
   - 説明文のコピー

## 3. 検索機能（最重要）

原典は pandas `Series.str.contains(search_word, case=False)` である。既定で **正規表現検索** かつ **大文字小文字無視**。`re.search` 相当（部分一致、先頭アンカーなし）。

### 3.1 検索対象列

- **検索する**: 列0（ポケモン名） **または** 列2（説明文）
- **検索しない**: 列1（ゲームタイトル）

例: `ファイアレッド` はゲームタイトルに多数存在するが、名前・説明文に無ければ 0 件。

### 3.2 ヒット条件

ある行がヒットするのは、ポケモン名または説明文のいずれかが検索パターンにマッチしたとき。

名前だけの一致、説明文だけの一致、両方一致、いずれも一覧に載る。

### 3.3 一覧の作り方

1. CSV 出現順でヒット行を走査する。
2. 列0の値の **初出順ユニーク** を一覧に出す（pandas `unique()` と同じ）。
3. ソートしない。全国図鑑番号順でも五十音順でもない。CSV の並びがそのまま順になる。

### 3.4 結果なし

ヒットが 0 件のとき、一覧に次の 1 行だけを出す。

`該当するデータは見つかりませんでした。`

### 3.5 空文字検索

空文字は正規表現として全文字列にマッチする。入力が空のまま検索すると **全 1,021 種** が一覧に出る。

### 3.6 大文字小文字・文字種

- 英字のみ `case=False`（`Sleep` と `sleep` は同じ）。
- **ひらがな／カタカナの相互変換はしない**。
  - `ピカチュウ` はヒットする。
  - `ぴかちゅう` はヒットしない。
- 名前はカタカナ、説明文は主にひらがななので、「たね」は説明文ヒット、「フシギダネ」は名前ヒット、という使い分けが原典の使い方そのもの。

### 3.7 正規表現

検索語は正規表現としてコンパイルする。

- `.` は任意の1文字なので、全件ヒットする。
- `フシギ` は `フシギダネ` / `フシギソウ` / `フシギバナ` にマッチする。
- 不正な正規表現（例: `(`）は原典では例外で検索処理が中断し、一覧は更新されない。Web 版も **一覧を変えず、直前の結果を残す**。

### 3.8 空白の扱い

- 入力の前後空白は trim しない。
- 説明文先頭のスペースはデータとして保持する。`うまれた` のような部分文字列なら、先頭スペースがあってもヒットする。

### 3.9 検索の実行タイミング

- 入力のたびに検索しない（ライブ検索なし、デバウンスなし）。
- **Enter**（入力欄にフォーカスがあるとき）または **「単語検索」ボタン** でのみ実行する。
- 実行のたびに、直前に使った検索語を保存する（詳細ハイライト用）。不正正規表現で失敗したときは保存しない。

### 3.10 代表例（原典と同じ結果になること）

| 検索語 | ユニーク件数 | 先頭の並び（抜粋） | 意味 |
| --- | --- | --- | --- |
| （空） | 1021 | フシギダネ, フシギソウ, … | 全件 |
| ピカチュウ | 4 | ピカチュウ, ライチュウ, パチリス, ミミッキュ | 名前一致 + 説明文に「ピカチュウ」と書かれた別ポケモン |
| でんき | 49 | ピカチュウ, ライチュウ, … | ひらがな説明文ヒット |
| 電気 | 55 | ピカチュウ, ライチュウ, … | 漢字説明文ヒット。`でんき` とは件数が違う |
| たね | 81 | フシギダネ, フシギバナ, アーボック, … | 説明文ヒット。名前に「たね」は無い |
| ファイアレッド | 0 | （メッセージ行） | ゲームタイトルは見ない |
| フシギ | 3 | フシギダネ, フシギソウ, フシギバナ | 名前の部分一致 |
| ぴかちゅう | 0 | （メッセージ行） | かな変換しない |
| . | 1021 | 全件 | 正規表現 |

## 4. 詳細表示

一覧行を **ダブルクリック** したとき、その行の表示文字列をポケモン名として詳細を開く。

### 4.1 詳細の抽出

原典は `df.iloc[:, 0].str.contains(pokemon_name, case=False)`。

- **完全一致ではない**。名前に対する正規表現部分一致。
- 例: `リザード` を開くと `リザード` と `リザードン` の行が混在する。
- 例: `ミュウ` を開くと `ミュウツー` が先に出る（CSV 上、ミュウツーの方が先）。
- 例: `ラッタ` を開くと `コラッタ` と `ラッタ` が両方出る。
- ヒット行は CSV 順のまま。バージョンでまとめたり、重複説明を除去したりしない。

### 4.2 詳細テーブル

| 列 | 見出し | 原典の幅 |
| --- | --- | --- |
| 列1（Game Title） | バージョン | 100px |
| 列2（Description） | 説明 | 600px |

0 件なら、バージョン空・説明 `該当するデータは見つかりませんでした。` の 1 行。

### 4.3 ハイライト

詳細を開いた時点の検索語 `search_word` を使う。

- 判定は **正規表現ではなく、大文字小文字無視の部分文字列**。
  - Python: `search_word.lower() in description.lower()`
- マッチした行の背景は `#cefff8`。
- 検索語が `.` でも、ハイライトは文字としての `.` がある行だけ（正規表現の任意文字ではない）。
- 検索語が空文字なら、空文字はどの文字列にも含まれるため **全行ハイライト**。

一覧側（ポケモン名リスト）はハイライトしない。

### 4.4 複数ウィンドウ

ダブルクリックのたびに **新しい詳細ウィンドウ** を開く。同じポケモンを何度開いてもよい。既存を使い回さない。

## 5. コピー

詳細ウィンドウでのみ有効。

- 右クリックメニュー: `コピー(Ctrl+C)`
- ショートカット: `Ctrl+C`（詳細ウィンドウにフォーカスがあるとき）
- 対象: **選択中行の説明列だけ**（バージョンはコピーしない）
- 行が選択されていなければ何もしない
- 右クリックは行選択を変更しない（原典の Treeview と同じ。選択済み行の説明をコピーする）
- 成功時、コンソールに次を出す（原典の `print` 相当）
  - `説明文をクリップボードにコピーしました。`
  - コピーした説明文そのもの

## 6. 初期状態

起動直後は検索しない。一覧は空。入力欄は空。

## 7. 非機能（Web 化に必要な範囲）

- 静的ファイルのみ（GitHub Pages）。サーバサイド検索はしない。
- CSV はブラウザで 1 回読み、以降はメモリ上で原典と同じ条件検索をする。
- 28,008 行の検索はボタン／Enter のたびに全件走査してよい（体感は即時）。

## 8. 明示的にやらないこと

原典に無い機能は追加しない。

- ゲームタイトル検索、タイプ検索、図鑑番号検索
- オートコンプリート、サジェスト、検索履歴
- ひらがな・カタカナ・漢字の正規化
- 一覧のソート、フィルタ追加、ページング
- 単クリックで詳細を開く
- 説明文中の検索語そのものを太字にする（行背景だけ）
