# UI / 使い心地要件定義書

機能要件・デザイン要件に加え、**操作したときにどう感じるか** を原典どおりに固定する。検索の手触りを最優先する。

---

## 1. 基本的な操作の流れ

1. ページを開く。灰色のウィンドウ `Pokedex Search` が出る。一覧は空。まだ何も検索されていない。
2. 入力欄をクリックし、調べたいポケモン名または説明文中の単語を入れる。
3. **Enter** を押す、または **単語検索** を押す。入力中に結果が変わってはいけない。
4. 一覧にポケモン名だけが並ぶ。説明文はこの画面には出ない。
5. 気になる名前を **ダブルクリック** する。
6. `{名前} の詳細` が別ウィンドウで開き、バージョンと説明が並ぶ。
7. 今の検索語を含む説明行だけが薄いミント色になる。名前検索で開いた場合、検索語が説明に無い行は白のまま。
8. 読みたい説明をシングルクリックで選び、右クリックの `コピー(Ctrl+C)` または Ctrl+C で説明だけコピーする。

この 8 歩以外の近道（入力と同時に絞る、シングルクリックで詳細、説明プレビュー）は作らない。

## 2. 検索の手触り（最重要）

### 2.1 「押したときだけ探す」

原典は `Entry` の `<Return>` とボタン `command` だけ。1 文字ごとに走査しない。

ユーザーが期待してよいこと:

- 打ち終わってから Enter で、一拍で一覧が入れ替わる。
- 打ちかけの途中結果は見えない。
- 前回の一覧は、次に Enter / ボタンするまで残る。

### 2.2 名前でも説明文でも同じ入力欄

ラベルが `ポケモン名or検索したい単語:` である意味を守る。

- カタカナの名前（`ピカチュウ`）を入れる → そのポケモンが出る。加えて、説明文にその名前が書いてある別ポケモンも出る。
  - `ピカチュウ` の結果は `ピカチュウ, ライチュウ, パチリス, ミミッキュ`
  - 「ピカチュウで検索したのにライチュウがいる」はバグではなく、ライチュウの説明にピカチュウと書いてあるから。
- ひらがなの単語（`たね`, `でんき`）を入れる → 図鑑文にその表記があるポケモンが出る。
- 漢字（`電気`, `種子` ではなくデータにある表記）は漢字説明の行だけ見る。
  - `でんき` と `電気` は件数が違う。かな図鑑と漢字図鑑が別行だから。

### 2.3 ゲーム名では探せない

`ファイアレッド` や `ソード` を入れても、それがゲームタイトル列にしか無いなら 0 件。

ユーザーが「バージョン名で絞る」と思って空振りする体験も原典と同じにする。バージョンを見るのは詳細ウィンドウに入ってから。

### 2.4 部分一致が常に効く

- `フシギ` でフシギダネ系列 3 種。
- 名前の途中一致も、説明の途中一致も同じエンジン。

### 2.5 正規表現がそのまま効く

上級者は正規表現を使える。知らない人は普通の単語を入れるだけで部分一致になる（日本語に正規表現メタ文字がほぼ無いため）。

- 空検索 → 全ポケモン。図鑑をざっと眺める手段。
- `.` → 同じく全件（任意文字）。ただし詳細のハイライトは「ピリオドという文字」がある行だけ、という食い違いがある。これも原典どおり。
- 壊れたパターン `(` は何も起きない（一覧が消えない）。エラーダイアログも出さない。

### 2.6 かな変換しない

`ぴかちゅう` では出ない。原典ユーザーは図鑑の表記（名前はカタカナ、本文はひらがな／漢字）に合わせて打つ。Web 版で勝手に正規化して「便利に」してはいけない。

### 2.7 並び順は「見つかった順」

ヒットした行を CSV の上から見て、新しい名前が来るたびに足す。

`たね` の先頭が `フシギダネ, フシギバナ, アーボック, …` になるのは、フシギソウの説明に「たね」が無く、アーボックの説明にはあるから。この違和感のある順も残す。

### 2.8 一覧は名前だけ

一覧を見て「どのゲームの、どの文がヒットしたか」は分からない。それが原典の情報の粒度。詳細を開いてミント色の行を探す、という二段構えが使い方の本体。

## 3. 一覧の操作

- シングルクリック: その行を選択（青）。詳細は開かない。
- ダブルクリック: 選択＋詳細ウィンドウ。
- キーボードの上下で選択が動いてもよい（OS のリスト相当）が、Enter で詳細を開く機能は原典に無いので必須ではない。
- 0 件メッセージ行も通常行。ダブルクリックすると、その文言で名前検索した詳細が開く（ほぼ空）。特別扱いでクリック無効にしない。
- 一覧を出し直すと選択は消える。スクロール位置も先頭に戻る。

## 4. 詳細ウィンドウの操作

### 4.1 開いた瞬間に見たいもの

- そのポケモン（および名前部分一致で巻き込まれたポケモン）の全バージョンの説明。
- 「今探していた単語」が本文に含まれる行だけミント色。
- スクロールすれば、色の付いた行／付いていない行が混在している。

使い方の典型:

1. `たね` で検索する。
2. フシギダネをダブルクリックする。
3. 「たね」と書いてある説明だけが色付き。漢字の「タネ」「種子」だけの行は色が付かない。

これが「検索語ハイライトは説明の部分文字列」という体験。

### 4.2 名前の部分一致で巻き込む

`リザード` を開くとリザードンの説明も同じ表に混ざる。ユーザーが「リザードだけ見たい」と思っても、原典はそう動かない。Web 版で完全一致に直さない。

### 4.3 ウィンドウの重なり

比較したくて何匹もダブルクリックできる。それぞれ独立にスクロール・選択・コピー・閉じる。メインの検索語は共有するので、どれを開いても同じ単語で色が付く。

詳細を開いたあとにメインで別の語を検索しても、**すでに開いている詳細の色は変わらない**（開いた瞬間の `search_word` を使う）。ただし原典は `self.search_word` を共有しているため、コピー対象の Treeview は最後に開いた詳細を指す、という実装寄りの挙動がある。Web 版では **各ウィンドウが自分の表と自分の選択を持つ** 方が、見た目の「別ウィンドウ」に忠実なので、コピーはそのウィンドウの選択行を使う。

### 4.4 コピーの手触り

- 説明文だけがクリップボードに入る。バージョン名は入らない。
- 成功しても画面上にトーストは出ない（原典は print のみ）。
- 右クリックした行が未選択なら、メニューは出るがコピーは空振りしうる。原典と同じ。コピーしたい行は先に左クリックする。

## 5. フォーカスとキーボード

| 操作 | 結果 |
| --- | --- |
| 入力欄で Enter | 検索。ボタンと同じ |
| 入力欄で IME 確定の Enter | 検索してよい（単語を打ち終わった操作） |
| メインで Ctrl+C | 詳細コピーは走らない |
| 詳細で Ctrl+C | 選択行の説明をコピー |
| Esc | 原典にバインド無し。詳細を Esc で閉じる機能は必須ではない |

Web ではページを開いたら入力欄にフォーカスしてすぐ打てるようにする。原典の Tk は自動フォーカスしないが、ブラウザでクリック必須にすると「すぐ検索する」使い心地が落ちるため、ここだけ Web 向けに合わせる。見た目は変えない。

## 6. 画面遷移で壊してはいけないこと

- 検索しても URL は変えなくてよい（原典に履歴が無い）。
- リロードすると未検索の空一覧に戻る。
- 詳細を閉じても一覧と検索語は残る。
- メインを操作しても開いている詳細は勝手に閉じない。

## 7. GitHub Pages 上での許容差（使い心地を変えない範囲）

| 原典 | Web |
| --- | --- |
| 毎回 CSV を読み直す | 初回に 1 回読む。データは静的なので結果は同じ |
| OS の別ウィンドウ | ページ内の 800×400 ウィンドウ。移動・前面化・複数枚は同じ |
| `clipboard_append` | Clipboard API。失敗時もコンソール出力は行う |
| コンソール print | ブラウザの開発者コンソール |

ポップアップ（`window.open`）はブラウザにブロックされやすく、二段操作の手触りが壊れるので使わない。

## 8. 受け入れの目安（使い心地）

次を人手でやって、原典と同じ「結果の顔」になること。

1. 起動直後、一覧が空で、入力して Enter するまで何も出ない。
2. `ピカチュウ` → 4 件で、ライチュウ等が混ざる。ライチュウの詳細を開くと、ピカチュウと書いた行だけミント。
3. `たね` → フシギダネ詳細で、かなの「たね」行だけミント。漢字行は白。
4. `ファイアレッド` → 見つからないメッセージ。
5. 空 Enter → フシギダネから始まる全件。詳細を開くと全行ミント。
6. ダブルクリックのたびに詳細が増える。
7. 説明を選択してコピーすると、貼り付け結果が説明文のみ。
